# Current state

Snapshot taken **2026-09-20**, at the end of a working session. Everything
below was checked against the working tree on the snapshot date, not recalled.

## One-paragraph summary

Horizon (renamed from Antler this session) is a working **pre-alpha API** with
two parts, memory and memory-aware agent routing, sold as one product. The
API, schema, auth, routing engine, tests, CI and a synthetic benchmark all
work. Routing decisions are now persisted and linked to their outcomes, pricing
is settled, and the benchmark reports a multi-seed spread rather than one lucky
run. No SDK exists, nothing is deployed, and there are no users.

## What exists and works

**API** (`horizon/api/routes/`), all under `/v1`, authenticated with an API key
(except signup):

- Organizations: open signup returning the first key once, `GET
  /organizations/me` (plan, typed limits, memories stored, routed decisions
  this month, executions recorded, executions with feedback), `POST /api-keys`
- Memories: create (embeds, dedupes near-copies ≥0.95 within a collection),
  semantic search with collection/user/session/tag filters, list, get, patch
  (re-embeds on content change), delete
- Agents: register (embeds name + description + capabilities), list, soft-disable
- Routing: `POST /route` returns `decision_id`, the chosen agent, a confidence
  and a full per-candidate `reason` including `exploring`; accepts an optional
  `min_similarity` override
- Executions: `POST /executions` reports an outcome, optionally linked to a
  `decision_id`; `GET /executions` returns history

**Routing engine** (`horizon/services/router.py`): a contextual bandit. Evidence
comes from a Beta posterior over similar past executions (similarity ≥0.75,
30-day half-life), scored by its optimistic bound (mean + 1.0·sd):
`score = 0.6·evidence + 0.3·capability − 0.1·cost`.

**Data layer**: Postgres 16 + pgvector with HNSW cosine indexes. Two migrations
covering organizations, api_keys, memories, agents, routing_decisions and
executions. Embedding dimension fixed at 1536.

**Benchmark** (`benchmarks/`): 1,000 tasks, 4 task families, 5 agents that
over-claim. Offline hash embeddings, through the real HTTP API, SQL and HNSW
path. Full numbers in `base/metrics.md`.

## Known gaps and loose ends

Gaps that block a public alpha:

1. **The evidence threshold has never been tested against a real embedding
   model.** `make similarity` shows why this matters: under paraphrased tasks,
   lexical similarity cannot separate related work from unrelated work at all,
   and 0.75 discards 76% of genuine evidence. Blocked only on `OPENAI_API_KEY`.
   This is `base/next-steps.md` step 1.
2. **Signup is open with no rate limiting.** Anyone can create orgs and spend
   the embedding budget.
3. **You can't revoke API keys.** `revoked_at` exists and auth checks it, but no
   endpoint sets it, and the `POST /api-keys` docstring promises revocation.
4. **No deploy path**: no Dockerfile, no hosted database.
5. **No SDK.** Callers hand-write the route → run → report loop.
6. **Plan limits are published but not enforced.** `PLAN_LIMITS` is returned by
   the API and nothing meters against it.

Smaller:

7. **Late feedback has no endpoint.** `Execution.feedback_at` exists; nothing
   can update `quality_score` after the fact.
8. **CI has never run.** The workflow is written but the repo has no GitHub
   remote history for it yet — confirm the integration tests *run* on the first
   push, not skip.
9. **The benchmark is not bit-reproducible.** HNSW search is approximate, so the
   same seed varies by up to ~1pp on final-250. Documented everywhere the
   numbers appear; not worth fixing, but never quote a single run as exact.
